# Docker Cheat Sheet & Guide for Saturday Smashers 🏓

Welcome to the Docker guide! This document explains how the different Docker files in this project work and provides a cheat sheet of the most common commands you'll ever need.

---

## 🏗️ 1. Understanding Our Docker Files

You have four main Docker-related files in this project. Here is what they actually do:

1. **`Dockerfile.dev`**: Builds the **Frontend for Development**. It installs all your `package.json` dependencies and runs `npm run dev` with Vite's hot-reloading enabled.
2. **`backend/Dockerfile`**: Builds the **Backend (FastAPI)**. It installs your `requirements.txt` Python packages and starts your Uvicorn server on port 8000.
3. **`Dockerfile` (Root)**: Builds the **Frontend for Production**. It runs `npm ci`, builds a highly optimized static bundle (`dist` folder), and serves it using NGINX (a ridiculously fast web server).
4. **`docker-compose.dev.yml`**: The orchestrator for **local development**. It reads `Dockerfile.dev` and `backend/Dockerfile` and maps your local code directly into the running containers. When you save a file in VS Code, the app updates instantly without needing a rebuild!
5. **`docker-compose.prod.yml`**: The orchestrator for **deployment**. Instead of building from source code, this file pulls your pre-built, optimized public images directly from Docker Hub (`nafsan/saturday-smashers-frontend:latest` and `backend:latest`).

## 🧑‍💻 2. Local Development Commands (`docker-compose.dev.yml`)

These are the commands you will use 99% of the time while actively coding on the project.

### Start the entire dev app (Frontend + Backend)

```bash
docker compose -f docker-compose.dev.yml up -d
```

- `-d` completely hides the logs so you can keep using your terminal.\*
- _Your website will be live at `http://localhost:5173`._

### Stop the app

```bash
docker compose -f docker-compose.dev.yml stop
```

### Stop AND completely delete the dev containers

```bash
docker compose -f docker-compose.dev.yml down
```

### IMPORTANT: What to do when you install a new npm package

If you run `npm install react-markdown` (or change `requirements.txt` in the backend), your running Docker container won't automatically know about it. You **must** rebuild the container image:

```bash
# Rebuild the frontend with the new package and restart it
docker compose -f docker-compose.dev.yml up --build -d frontend

# Or rebuild the backend if you added a Python package
docker compose -f docker-compose.dev.yml up --build -d backend
```

## 🚀 3. Publishing & Production Commands (`docker-compose.prod.yml`)

When you are ready to publish new features to the world, follow these steps to update your Docker Hub images.

### Step 1: Build the optimized Production Images

This creates the final, compressed application using `Dockerfile` (frontend Nginx) and `backend/Dockerfile`.

```bash
# 1. Build Frontend
docker build -t nafsan/saturday-smashers-frontend:latest -f Dockerfile .

# 2. Build Backend
docker build -t nafsan/saturday-smashers-backend:latest -f ./backend/Dockerfile ./backend
```

### Step 2: Push the updates to Docker Hub

Upload your new code to your public repository:

```bash
docker push nafsan/saturday-smashers-frontend:latest
docker push nafsan/saturday-smashers-backend:latest
```

### Step 3: Run the Production App

If someone clones your repository from GitHub, all they have to do to run the real production setup is:

```bash
docker compose -f docker-compose.prod.yml up -d
```

_Because they are using the `.prod.yml` file, Docker will simply download your pushed images from Docker Hub instead of trying to compile Python and React on their computer!_

## 🛠️ 4. Handy Troubleshooting Commands

### Look at the logs (Very useful for debugging!)

If something is crashing, you can print the logs generated by your apps:

```bash
# View all logs
docker compose -f docker-compose.dev.yml logs -f

# View only the backend logs (FastAPI print statements, errors, etc.)
docker compose -f docker-compose.dev.yml logs -f backend

# View only the frontend logs
docker compose -f docker-compose.dev.yml logs -f frontend
```

_(Press `Ctrl+C` to exit the log viewer)_

### Delete all unused Docker data (Free up space!)

Docker caches builds, so it can quickly take up gigabytes of space on your hard drive. Run this once a month to safely delete stopped containers and old unused images:

```bash
docker system prune -a
```
